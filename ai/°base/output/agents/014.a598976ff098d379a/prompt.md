### `history_master.py` — implement per the plan:

- **No `git rebase --exec`.** Drive everything from a Python loop using `git_ops.cherry_pick`/`cherry_pick_continue`/`cherry_pick_abort` per ordinary commit, and the merge-recreation procedure below for base-merges. This avoids the two real failure classes documented in `ai/°base/errors/16.txt`/`17.txt` (read them briefly for context) that a `rebase_strip_claude_authorship.py`-style `--exec` callback already hit.
- `is_base_merge(sha, cwd) -> bool` — `trailers.read_trailer_value(git_ops.commit_message(sha, cwd), "X-Base-History-Merge-Kind", cwd) == "base-merge"`.
- `recreate_base_merge(old_merge_sha: str, onto: str, cwd: Path) -> str` — read the recorded `X-Base-History-Merge-Sha` trailer value (`base_old_sha`) from `old_merge_sha`'s message. Run `git_ops.checkout_branch`-free approach: since you're building history_master's new tip as a detached sequence (not necessarily checked out), you'll need to actually checkout a working branch to run `git merge --no-commit`/`git cherry-pick` against (they're not pure plumbing, they mutate the working tree/index) — checkout a scratch branch pointed at `onto` first (e.g. `git_ops.create_branch("refs/heads/_base_split_scratch", onto, cwd)` then `git_ops.checkout_branch("_base_split_scratch", cwd)`), run `git_ops.merge_no_commit(base_old_sha, cwd)`; if it returns 0 (clean merge), commit with `git commit --no-edit` (via a small local subprocess call, or synthesize via `git_ops.commit_tree` reading the resulting index tree — simplest is an actual `git commit --no-edit` subprocess call since you're on a real checked-out branch at this point) then re-attach trailers (`X-Base-History-Merge-Kind`, `-Sha`, plus new `X-Base-History-Merge-Replayed-From: <old_merge_sha>`) via amend; if it conflicts, for each conflicting path (from `git status --porcelain=v1` or `git diff --name-only --diff-filter=U`), resolve by writing `git_ops.show_path_at(old_merge_sha, path, cwd)`'s bytes to that path and `git add`-ing it, then commit the same way. Clean up the scratch branch ref afterward. Return the new commit sha.
- `replay_commit(sha: str, onto: str, cwd: Path) -> str` — checkout the scratch branch at `onto`, `git_ops.cherry_pick(sha, cwd)`; if conflict (nonzero returncode), raise a clear exception carrying enough info for the CLI layer to print recovery instructions and persist state (see below) — do NOT silently auto-resolve ordinary conflicts, only base-merges get automatic resolution. On success, message is preserved verbatim by cherry-pick automatically (this is intentional — trailers like `X-Base-Split-Source` on history commits must survive byte-for-byte). Return the new tip sha.
- `find_newly_merged_clean_branches(old_master_sha: str, new_master_sha: str, cwd: Path) -> list[tuple[str, str]]` — walk `git_ops.rev_list_reverse(f"{old_master_sha}..{new_master_sha}")`, for each commit check `trailers.read_trailer_value(git_ops.commit_message(sha, cwd), "X-Base-Split-Clean-Branch", cwd)`; if present, yield `(commit_sha, branch_name)`.
- `has_merge_marker(history_master_tip: str, clean_merge_sha: str, cwd: Path) -> bool` — walk back from `history_master_tip` (bounded search, e.g. `git_ops.rev_list_reverse` from some reasonable ancestor bound, or simply grep all of history_master's commits — a full walk is fine for realistic branch counts) checking each commit's `X-Base-Split-Merge-Marker-For` trailer for a match.
- A small resumable-state helper: write/read a JSON file at `repo_root / ".git" / "BASE_SPLIT_HISTORY_MASTER_STATE"` recording `{"remaining": [...], "tip": ..., "force_merge": [...], "original_sha": ...}`. `update_history_master(*, repo_root, main_branch, force_merge: list[str] = [], pull_master: bool = False, pull_base: bool = False, yes: bool = False, continue_: bool = False, abort: bool = False, dry_run: bool = False) -> dict` — the top-level entry point implementing the ordering algorithm from the plan (master commits first via literal ancestry on first run, else replay `old_master..old_history_master` onto `new_master`; then for each newly-merged branch not already marked (or in `force_merge`), replay its history branch's unique commits then add an empty merge-marker commit; base/base folding is a separate final step only if `new_base_sha` isn't already an ancestor). For the very first run (`ai/history/master` doesn't exist / `git_ops.rev_parse` returns None), just `git_ops.create_branch(branches.history_name(main_branch), master_tip, cwd)` — no replay needed. Handle `--continue`/`--abort` by reading/clearing the state file. For interactive pull prompts (steps "pull master? [y/N]", "pull base? ### `rebase_to_master.py` — implement per the plan:

- `rebase_branches_to_master(base_branch: str, *, repo_root: Path, main_branch: str, yes: bool = False, dry_run: bool = False) -> dict` — per branch-name: clean exists? `git rebase <main_branch>` on it (real `git rebase` subprocess is fine here, this is a normal single-branch linear rebase, not the base-merge-recreation case) : else report skipped. history exists? `git rebase <history_name(main_branch)>` on it : else report skipped. unclean exists AND history rebase succeeded? `git rebase <history's new tip>` on it : else report skipped (with a reason distinguishing "history missing" vs "history rebase failed").

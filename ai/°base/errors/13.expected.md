# Notes

## Codex payload format differs from Claude

Claude's `tool_response` for `AskUserQuestion`:
```json
{
  "answers": { "Question text?": "Selected label" },
  "annotations": { "Question text?": { "notes": "...", "preview": "..." } }
}
```

Codex's `tool_response` for `request_user_input`:
```json
{
  "answers": { "question_id": { "answers": ["Selected label"] } }
}
```

Key differences:
- Answers keyed by `id` field on each question, not by the `question` text.
- Answer value is `{"answers": ["label"]}` (array, single-element for single-select).
- Questions carry an `id` field alongside `question` text and `header`.
- No `annotations` key — Codex has no notes or preview-selection mechanism.
- For multi-select, `answers` array would contain multiple labels in click order.

## Hook normalization needed

For the hook to render Codex payloads correctly it must:
1. Build an `id → question_text` map by iterating `tool_input["questions"]`.
2. Rekey `tool_response["answers"]` from id-keyed to question-text-keyed.
3. Unwrap each `{"answers": ["label"]}` to the string `"label"` (single-select)
   or the joined string `"A, B, C"` (multi-select, preserving array order as click order).

Until that normalization is added, the hook falls through to the `isinstance(raw_response, dict)` guard, passes `{}` as `tool_response`, and renders all options unchecked with no answers in the summary — a visual no-op, not a crash.

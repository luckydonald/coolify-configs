Notes on what changed vs. `18.md`:

- The full "before" ref table + `git update-ref` rollback block, and the full "before | after"
  summary table, no longer print to the console at all -- they're always written in full to
  `.rebase-recovery.tmp` (at `DEBUG`), alongside every underlying `git` invocation (argv,
  returncode, stdout/stderr on failure) and per-step timing. The console only gets the one-line
  pointer to that file (`snapshotted N ref(s) -> ...`).
- Each step is narrated live (`[i/N] <kind> <sha> '<subject>'` -> `ok`/`CONFLICT`) instead of
  running silently until a final dict.
- The conflict result carries the same human-readable message
  `CherryPickConflict` already built internally (previously discarded by a bare
  `except CherryPickConflict:` in `_run_steps`) -- surfaced as `== CONFLICT ==` with exactly two
  actionable recovery commands, plus a pointer to the full manual-rollback option.
- Separately (found live in the `ssp` repo while fixing this): if the state file claims a pending
  cherry-pick/merge but git shows no `CHERRY_PICK_HEAD`/`MERGE_HEAD` in progress (e.g. someone ran
  a raw `git cherry-pick --abort` by hand instead of this tool's own `--abort`), `--continue` now
  raises a clear error telling you to run `--abort` to clear the stale state, instead of trying a
  doomed `git cherry-pick --continue` and failing confusingly.
